> Deep coal mining faces rising rockburst risk as depth increases. Mine sites continuously stream Acoustic Emission (AE) and Electromagnetic Radiation (EMR) signals, but the raw data is flooded with duplicates, dropouts and machine interference. This write-up walks through a full pipeline: cleaning ~600k samples with clustering and IQR outlier rejection, separating interference (C) from precursor (B) signals with a sliding-window variance threshold, fitting the trend with linear regression, and finally scoring the probability of a precursor at each collection tick using a weighted grey prediction model.

## 一、前言：井下信号很多，但有用的没几条

煤炭深部开采里，地应力随深度往上堆，冲击地压这种煤岩动力灾害一旦发生就是事故级别的。工程上能依赖的"先知"，主要是两路监测信号：

- **声发射 AE**：煤岩体破裂时释放的弹性波强度；
- **电磁辐射 EMR**：裂隙扩展、电荷迁移产生的电磁信号。

这两路信号在冲击发生前数天会出现"趋势性前兆"。但真到数据落地才发现，原始流根本没法直接用——同时间戳重复采样一堆、传感器断线冒零值、固定设备运转产生的干扰信号混在里面。监测数据被分成了 5 类：A 正常、B 前兆、C 干扰、D 断线、E 休息。

我的任务就是把这堆"脏信号"洗干净、把干扰和前兆区分开，最后给出每个采集时刻出现前兆的概率。

## 二、环境与架构：一套数据流水线

整个方案不依赖昂贵的专用平台，就是常规的数据处理栈：

| 环节 | 工具/方法 | 说明 |
|---|---|---|
| 数据清洗 | 聚类分析 + 透视表 | 按时间戳汇总重复采样 |
| 异常值判定 | IQR 四分位距 | 偏态分布不用 3σ，改用四分位距 |
| 趋势平滑 | 滑动平均法 | 3600s（60 分钟）时间窗口 |
| 趋势建模 | 一元线性回归 | 拟合前兆信号随时间的上升斜率 |
| 概率打分 | 熵值法加权 + 灰色预测 GM(1,1) | 5 个特征加权求和得前兆概率 P |

数据预处理这一段是后面所有分析的地基，流程长这样：

![数据预处理流程图：空值定位→聚类去重→正态/偏态分布判定→IQR 异常识别](/images/rockburst-preprocess-flow.png)

*附件 1~3 全部数据先空值定位，再用聚类分析法把同一时间戳的重复采样按平均值汇总成一条；最后按分布形态选 3σ 或 IQR 做异常值剔除。*

光附件 1 的 EMR 就有 610932 条原始记录，聚类去重后压到 571675 条；AE 侧 611904 条压到 572247 条。重复采样不是噪声那么简单，不压掉后面的均值、方差全是错的。

## 三、Step 1：先把"干扰信号"从信号里剥出来

干扰信号（C 类）有三个很扎眼的统计特征：平均值和标准差远大于 A 类正常信号、数值跨度极大、相邻采样差值的均值也大。看一组真实统计：

| 类别 | 平均值 | 方差 | 最小值 | 最大值 | 差值均值 |
|---|---|---|---|---|---|
| EMR-A（正常） | 45.82 | 46.75 | 29.25 | 64.36 | 1.97 |
| EMR-B（前兆） | 50.71 | 637.99 | 11.68 | 147 | 4.32 |
| EMR-C（干扰） | 77.47 | 7996.78 | 0 | 500 | 11.64 |
| AE-A（正常） | 36.66 | 4.38 | 31 | 42.72 | 0.53 |
| AE-C（干扰） | 63.23 | 8789.84 | 27 | 500 | 8.40 |

C 类方差（7996 / 8789）比 A 类（46 / 4）高了两个数量级——**干扰的本质是"剧烈抖动"**。

思路是：对附件 2 的无标签数据，用 3600s 滑动窗口算每段的动态均值、差值和方差，再按 A:B:C 的方差比例设阈值，超过阈值且在时间上连续的段，就标为干扰区间。筛选流程：

![干扰信号筛选流程图：3600s 窗口汇总→阈值判断→时间/月份过滤→连续值遍历](/images/rockburst-screening-flow.png)

阈值不是拍脑袋定的，而是 `阈值 = 干扰信号均值 + k × 偏差`，k 取 2。超过阈值的连续段，用一段递归遍历把"连续日期"合并成区间：

```java
// 找到连续的时间点，合并成 "start-end" 形式的区间
public static String convert(String[] days, int index) {
    int end = index;
    if (days.length == index) return "";        // 遍历完数组
    for (int i = index; i < days.length; i++) {
        if (i < days.length - 1) {
            Date d1 = DateUtils.addDate(DateUtils.format(days[i], "yyyyMMdd"), 1);
            Date d2 = DateUtils.format(days[i + 1], "yyyyMMdd");
            if (d1.getTime() == d2.getTime()) {
                end = i;                         // 相邻天连续，继续扩
            } else {
                if (i > index) end = end + 1;
                break;
            }
        }
    }
    if (index == end)                             // 不连续：单点
        return days[index] + "," + convert(days, end + 1);
    else                                          // 连续：合并成区间
        return days[index] + "-" + days[end] + "," + convert(days, end + 1);
}
```

这样最终筛出 EMR 最早的 5 个干扰区间，例如 `2022-05-01 10:57:50 ~ 11:12:29`、`2022-05-14 08:11:24 ~ 09:24:34`；AE 侧则是 `2022-05-09 08:00:07 ~ 09:58:57` 等。

## 四、Step 2：用线性回归刻画前兆信号的"上升趋势"

剥掉干扰后，再看 B 类前兆信号。它和干扰的区别在于：不是乱跳，而是**在一个相对稳定的基线上，某段时间内持续、循环地往上走**。

我对附件 1 里所有 B 类段分别做一元线性回归 `y = a + b·t`（t 为时间，y 为信号强度）。EMR 的 B 类一共切出 31 段前兆，AE 的 B 类切出 9 段：

![多段 B 类前兆信号的线性回归折线图，可见数段明显抬升的趋势](/images/rockburst-linear-regression.png)

*横轴是采样点序号，纵轴是信号强度。那些突然跳到 400 附近的青色/品红色高幅段就是前兆，细线是各自的回归拟合。*

以 AE-B 为例，回归结果 n=82，`R²=0.721`，调整 R²=0.687，`F=20.721 (P=0.000)`，VIF 全部小于 10——说明 B 类信号和时间确实存在显著线性关系，没有多重共线性问题。总结出的前兆时间特征：

- **EMR**：以分钟为单位持续出现，一般持续 4~15 小时，一个月最多两段；
- **AE**：至少持续 2 小时，一般持续 2~8 小时，一个月最多一段。

## 五、Step 3：灰色预测给每个采集时刻打"前兆概率分"

前两步解决了"长什么样"，第三步要回答"**现在这一刻，出现前兆的概率是多少**"。附件 3 给了 5 个不连续时间段、共 10 组 EMR/AE 序列。做法是从 5 个维度分别打分再加权：

![前兆信号概率预测流程图：特征提取→显著性加权→附件3 数据分析→灰色预测→输出概率P](/images/rockburst-probability-flow.png)

五个维度的权重用熵值法定（离散度越大、权重越高）：

| 特征 | EMR 权重 | AE 权重 |
|---|---|---|
| 最大值/最小值 | 20 | 15 |
| 标准差 | 28 | 18 |
| 平均值 | 15 | 22 |
| 未来预测平均值（GM(1,1)） | 20 | 15 |
| 拟合系数（趋势） | 17 | 30 |

"未来预测平均值"这一项交给灰色预测 GM(1,1)——小样本、贫信息场景下它不需要大样本就能外推一步趋势。调用很轻：

```python
import pandas
from spsspro.algorithm import no_parameter_test

# 灰色预测：对短序列外推下一步均值
data = pandas.Series([1, 2, 3, 4, 5], name="A")
index = pandas.Series(["1", "2", "3", "4", "5"], name="B")
print(no_parameter_test.grey_forecasting_analysis(data, index))
```

把 P1（范围）、P2（标准差）、P3（平均值）、P4（灰色预测均值）、P5（趋势方向）加权相加，就得到每个时间段最后时刻出现前兆的概率。比如 2023-03-30 23:58 那一刻：EMR 概率 29.45%，AE 概率 53.27%；2023-02-11 23:59 一刻两路都接近 48%。哪个时刻分高，就优先盯哪个时刻。

## 六、踩坑实录

**坑 1：偏态分布硬套 3σ，异常值漏杀一半**

一开始图省事想全用 3σ 原则判异常值，结果 S-W、K-S 检验全是 `P=0.000***`——样本根本不正态。正因为数据严重右偏（EMR-A 偏度 4.15、峰度 30.1），才改用 **IQR 四分位距**：落在 `[Q1-1.5IQR, Q3+1.5IQR]` 之外才记为异常。这一步光 EMR-A 就剔掉了 9259 个异常点，EMR-B 剔了 842 个。**判分布形态要先做检验，别默认正态。**

**坑 2：阈值写死一个数，干扰和前兆分不出来**

如果所有时间段共用一个固定阈值，跨季节、跨工作面的数据直接乱套。最后改成"以各自 A:B:C 的方差比例为标尺、在本时间段内相对比较"，再加 `k=2` 的裕度——阈值是**随段自适应**的，不是全局常数。

**坑 3：聚类去重时把"真异常"一起平均掉了**

预处理时发现，IQR 剔出来的异常值和 C 类干扰在时间上并不独立，一旦去重时把它们和正常值一起平均，干扰特征就被稀释了。处理方式是：去重只针对"同一时间戳的重复采样"，异常值判定单独做，两者不混在一起。

## 七、小结与思考

这套流水线最终跑通了三件事：

1. **清洗**：60 万级样本经聚类去重 + IQR 判异，压到可用规模；
2. **识别**：用滑动窗口方差 + 连续区间遍历，把干扰、前兆各自的 5 个最早区间落了地；
3. **预测**：熵值法加权 5 特征 + GM(1,1) 灰色预测，给每个采集时刻一个前兆概率分。

回头看，最值钱的教训是**特征工程比模型本身重要**——把"干扰是高方差抖动、前兆是持续上升趋势"这两件事用方差、斜率、连续性刻画清楚，后面哪怕模型很朴素也能出结果。真要再往上做，我会接入实时流式计算（Flink 之类）把这套离线阈值判据变成在线告警，而不是停留在事后批处理。
