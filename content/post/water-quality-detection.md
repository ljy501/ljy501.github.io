> Most farm-pond water quality monitoring still relies on fixed-point sensors and manual dipping, which misses the spatial variation across depth and location. This project built a bionic robotic fish on an STM32F407 (Cortex-M4) that cruises the pond on a GPS-planned path, fuses pH, temperature, dissolved oxygen, depth and light readings, streams video over 2.4 GHz wireless, and displays everything on an LVGL touch-screen controller. This write-up covers the power tree, the multi-sensor board, the radio link, and the on-device GUI port.

## 一、前言：固定探头测不准鱼塘的"立体水质"

水产养殖里，水温、溶氧、pH、氨氮这些指标直接决定鱼会不会翻塘。但传统做法是在塘边插几个固定探头——**一个点的数值代表不了整个塘**，不同深度、不同位置差得远。

我们的思路是把整套检测装置做成一条能自己游的"机器鱼"：沿着预设路径巡航，多点采样，水下摄像头全程开着，数据实时回传到手持控制器。这篇只聊技术集成那部分——硬件怎么供电、一堆传感器怎么挂到一颗 MCU 上、无线链路和图形界面怎么跑起来。

## 二、环境与架构：鱼端和控制端是两个 MCU

整机是**集散式控制**：鱼端一颗 STM32F407VGT6 管采集与推进，遥控器一颗 STM32F407VET6 管人机交互，两端靠 2.4G 无线打通。

| 模块 | 型号/器件 | 作用 |
|---|---|---|
| 鱼端主控 | STM32F407VGT6 (Cortex-M4) | 采集传感器、驱动电机 |
| 控制端主控 | STM32F407VET6 | 摇杆、触屏、数据存储 |
| 无线链路 | NRF24L01（2.4G）+ JDY 蓝牙 | 鱼 ↔ 控制端通信 |
| 视觉 | OV7670（自带 FIFO） | 水下实时画面 |
| 姿态 | MPU6050 六轴 | 转向角度参考 |
| 定位 | ATGM332D（GPS+北斗双模） | NMEA 协议，巡航导航 |
| 深度/压力 | MS5803 | 0~30m 水深，12μbar 分辨率 |
| 水质 | ADC0809 pH/温度 | pH 0~14，温度 0~80℃ |
| 光照 | GY-302/BH1750 | 水下光照强度 |
| 系统 | FreeRTOS + LVGL | 任务调度 + 图形界面 |

## 三、Step 1：先把电源树捋明白——12V 怎么降到 3.3V

水下设备最怕供电不稳。板上同时有 12V 电机、5V 显示屏、3.3V MCU 和摄像头，一个电源直接供是不可能的，必须做两级降压：

```text
外置电源 12V
   │
   ├──► 电机（12V 直供，不经过稳压）
   │
   └──► LM2596 开关降压（输出 5V / 3A）
            │
            ├──► 4.3 寸 IPS 屏（5V）
            │
            └──► AS1117 线性稳压（5V → 3.3V）
                     │
                     └──► STM32F407、OV7670 摄像头（3.3V）
```

这里的分工很明确：**大电流开关负载用开关电源 LM2596 提效率，小电流敏感模拟/数字部分用 AS1117 线性稳压求干净**。AS1117 带过流保护，输出精度也够摄像头和 MCU 这种敏感器件用。如果图省事全用 LDO，3.3V 那路的发热和纹波会很难看。

## 四、Step 2：多传感器怎么挂到一颗 MCU 上

鱼身上挂了七八个传感器，总线各不一样，得一个个对：

- **pH/温度（ADC0809）**：8 通道 8 位 ADC，复合玻璃电极采水溶液 H⁺ 浓度，功耗低；
- **MPU6050**：I²C 挂六轴，实时回传姿态，给鱼的转向角度做闭环参考；
- **ATGM332D GPS**：串口走 NMEA 协议，GPS+北斗双模，初始化先搜星数，再把经纬度喂给巡航算法；
- **MS5803 压力传感器**：I²C，量程 0~30m 水深、精度 ±0.1%FS、12μbar 分辨率，自带温度补偿和数字校正，水下防水可靠；
- **OV7670 摄像头**：SCCB 总线控制，关键是它**自带 FIFO 缓存芯片**——这意味着不用 MCU 跑高速 IO 去硬啃像素时序，普通单片机也能把一帧图像读出来。

![OV7670 摄像头模块实物，板载 FIFO 让低速 MCU 也能采图](/images/waterquality-ov7670-camera.png)

*OV7670 模块：自带 FIFO 是它能在 STM32 上跑起来的关键，否则图像采集会吃掉大半 CPU。*

巡航逻辑是状态机：初始化各传感器 → 按手柄在屏上规划的路径/深度/速度出发 → 到预设点定点采 pH、溶氧、温度 → 把经纬度和水质绑定成一条记录 → 无线回传。控制端一旦收到手动指令，立刻中断当前自动任务。

## 五、Step 3：LVGL 上位机界面怎么画出来

操作界面用 LVGL 绘制，分三页：主界面（实时摄像头画面 + 水质数据）、功能设置（传感器开关、巡航预设、历史数据）、用户信息。先在 PC 上用 LVGL Simulator 把界面调通，再移植到目标板：

![LVGL 上位机监视器画面：左主界面实时水下摄像头，右侧数据面板显示 temp/PH/light/O2，右下角 33FPS 25%CPU](/images/waterquality-lvgl-ui.png)

*PC 端模拟监视器：主界面挂实时摄像头流，右侧数据面板实时刷新 temp 20.2、PH 7.1、light MID、O₂ 6.8mg/L，底部状态栏 33 FPS、25% CPU——说明在 STM32 上跑这套 UI 负载还很有余量。*

控制器本身是一块双面布板：双摇杆做方向、4.3 寸电容触屏做设置、NRF24L01 + 蓝牙双通道通信、自带 Flash 存历史数据：

## 六、踩坑实录

**坑 1：3.3V 供电纹波大，摄像头花屏**

一开始 3.3V 直接从开关电源后级取，OV7670 出来的画面满屏横纹。原因是开关电源的开关噪声没滤干净就喂给了敏感模拟前端。最后改成 **LM2596 降到 5V 后，再经 AS1117 线性稳压二次滤波到 3.3V**，纹波压下去画面才干净。模拟和数字电源一定要分级，别图省事。

**坑 2：摄像头采样卡死 MCU**

OV7670 如果不带 FIFO，每一帧像素都得靠 MCU 用 IO 翻转实时锁存，CPU 直接被打满、传感器任务全部饿死。这个模块选的时候专门挑了**带 FIFO 版本**，图像先在片上缓存，MCU 再慢慢读，一下子把实时性压力卸掉了。

**坑 3：水下定位漂移，巡航走飞**

GPS 在水面还行，入水后信号会衰减。靠 MPU6050 的六轴姿态做航位推算补正——GPS 给绝对经纬度，IMU 给短时间内的相对航向和速度，两者融合才不至于让鱼"游飞"。纯靠 GPS 在水面下是不可靠的。

## 七、小结与思考

这条机器鱼最终把分散的几块拼到了一颗 MCU 上：

1. **电源树**：12V → LM2596(5V) → AS1117(3.3V)，开关与线性分工；
2. **多传感器融合**：I²C 挂 MPU6050/MS5803，串口走 GPS NMEA，SCCB 控 OV7670；
3. **无线 + 上位机**：NRF24L01 2.4G 双向链路，LVGL 在 STM32 上跑出 33 FPS 的实时监控界面。

回头看，嵌入式集成最磨人的从来不是"点不点亮"，而是**供电质量、实时性分配和总线冲突**这三件事。真要再迭代，我会把数据回传接到物联网云平台，让养殖户在手机上看鱼塘水质曲线，而不只是站在塘边盯那块手持屏。
