> This network design project covers a government complex of 5000+ staff across several adjacent buildings, replacing a 2003-era network with an 8 million-yuan rebuild. The write-up goes from requirement analysis through a core/distribution/access three-tier topology, VLAN and IP addressing for six departments, Cisco device selection totaling 4.63 million yuan, five-subsystem structured cabling, and edge firewall deployment.

## 一、前言：一张 2003 年的老网，已经撑不住政务数字化

这个项目的背景很典型：某政府机构位于城市核心区，里面塞了政务审批、民生服务、应急管理等多个职能部门，**超过 5000 名工作人员**，办公地点散布在多栋相邻的办公楼里。

而它的网络基础设施是 **2003 年建的**。到了政务全面数字化的今天，问题集中爆发：业务高峰期带宽不够、老设备频繁死机掉线、安全防护漏洞百出、IP 地址乱分配还冲突。这次改造项目预算 **800 万**，分阶段实施，目标是建一张高速、稳定、安全的现代化政务网络。

## 二、需求分析：先把"痛"落成清单

设计之前先做现状调研，问题归纳成七类：

| 现状问题 | 具体表现 |
|---|---|
| 带宽限制 | 视频会议卡顿、大文件传输慢 |
| 稳定性差 | 老设备频繁死机、掉线，排障耗时 |
| 安全薄弱 | 易受攻击，政务信息有泄露风险 |
| 管理混乱 | IP 随意分配、冲突频发，权限控制松散 |
| 视频会议体验差 | 卡顿延迟，远程协作效率低 |
| 大数据处理受限 | 政务数据量增长，网络扛不住 |
| 资源分配不均 | 关键部门拿不到足够带宽 |

再把用户角色拆细：业务办理人员要稳定高速的在线审批、服务窗口人员要秒开业务系统、决策人员要高可靠的数据通道、远程办公人员要安全接入、访客要能上公共网但不碰内网、IT 维护人员要集中监控和备份恢复。**每一类人的 SLA 要求不一样，后面的拓扑设计就是为这些差异服务的。**

## 三、逻辑设计：核心、汇聚、接入三层砍下去

整体架构采用经典三层模型，设计原则是四个词：开放性（标准协议、可互联）、可管理性（集中监控）、可扩展性（预留冗余）、安全性（VLAN + 防火墙隔离）。

**核心层**是高速交换主干，重点是冗余和可靠性。配置两台三层交换机，用**链路聚合**互联，每台分别连路由器和服务器接入交换机。核心同时承担 DHCP，给各子网动态分配地址。

**汇聚层**是每栋楼/每个部门的汇聚点，每个部门一台三层交换机，**双上行到两台核心**做线路冗余；汇聚和接入之间构成环路，靠 **STP 协议**保证一条链路断了另一条顶上，整网不瘫痪。

**接入层**直接面对终端，主打性价比和即插即用，按楼栋划分 VLAN，每层设备间一台接入交换机上连汇聚、下连房间终端。

![政府网络拓扑：核心交换机双上联出口网关，三 ISP 出口，各部门接入交换机挂终端](/images/netplan-topology.png)

*Packet Tracer 拓扑：Multilayer Switch0 当核心，下行三台接入交换机分接政务审批/民生服务/应急管理部门，上行 2960-24PS 出口网关再连电信/移动/联通三条 ISP*

## 四、VLAN 与地址规划：六个部门六个广播域

VLAN 划分充分考虑部门职能差异，不同部门之间资源天然隔离。主办公区的规划如下：

| 部门/区域 | IP 段 | VLAN 号 | 信息点 |
|---|---|---|---|
| 政务审批部门 | 192.168.1.0/24、192.168.2.0/24 | VLAN1000 | 1000 |
| 民生服务部门 | 192.168.3.0/24、192.168.4.0/24 | VLAN2000 | 1000 |
| 应急管理部门 | 192.168.5.0/24、192.168.6.0/24 | VLAN3000 | 1000 |
| 办公区 A | 192.168.7.0/24、192.168.8.0/24 | VLAN4000 | 1000 |
| 办公区 B | 192.168.9.0/24、192.168.10.0/24 | VLAN5000 | 1000 |
| 办公区 C | 192.168.11.0/24、192.168.12.0/24 | VLAN6000 | 1000 |

编址逻辑很直白：**每个部门两个 C 类子网、预留 1000 个信息点**，既容纳当前终端，又给未来五年的扩展留足余量。服务器区则统一用私网地址（10.0.0.250–253），靠 NAT 对外发布。

## 五、物理设计与设备选型：463 万怎么花

选型思路是分层的：核心层要高性能高可靠，接入层要低成本高端口密度。整套设备清单：

| 网络设备 | 型号 | 单价 | 数量 | 小计 |
|---|---|---|---|---|
| 核心交换机 | Cisco WS-C3850-24T-S（24 口千兆，可万兆扩展） | 3 万 | 6 | 18 万 |
| 汇聚交换机 | Cisco WS-C3750X-24T-L（4 个可选上行模块） | 1.3 万 | 90 | 117 万 |
| 接入交换机 | Cisco WS-C2960X-48TS-L（48 口千兆 + 4 SFP） | 0.9 万 | 360 | 324 万 |
| 出口路由器 | Cisco 2811（内置防火墙） | 0.5 万 | 1 | 0.5 万 |
| 防火墙 | Cisco ASA5512-K8（并发 10 万、吞吐 1Gbps） | 3.5 万 | 1 | 3.5 万 |
| **合计** | | | | **463 万** |

服务器侧统一用戴尔 PowerEdge R710（Xeon E5620 / 4GB / 1TB），四台分别扛 Web、DNS、Email、FTP 四类服务，地址固定在 10.0.0.250–253，操作系统选 Windows Server 2022。

## 六、综合布线：隐蔽工程也是设计对象

弱电部分采用超五类非屏蔽方案：楼内数据主干走 **6 芯室内多模光纤**，语音主干走 3 类 100 对大对数电缆，水平线缆用超五类非屏蔽双绞线。整栋楼五层、层高 3.4–3.6 米，每个房间 3 个数据点 + 2 个语音点，网络中心机房设在行政楼 A 楼一层。

布线按五个子系统拆：垂直主干（光纤竖井）、水平子系统（直接埋管）、管理间子系统（每层电信间配线架）、工作区子系统（RJ45 信息插座）、设备间子系统（19 英寸标准机柜）。端接线序这步最容易被新手搞错：

![RJ45 插头 T568A 线序：一端 T568B、另一端 T568A 即为交叉线](/images/netplan-rj45-wiring.jpeg)

*交叉线两端一端 T568B、一端 T568A，用于电脑直连电脑、交换机直连交换机，同类设备互连别用错线序*

## 七、安全设计：边界两道闸

安全方案的目标是不影响业务的前提下全面控网：数据传输加密、边界网关做病毒与垃圾过滤、识别 DDoS 和 SQL 注入这类恶意流量、全程留日志供审计。

最关键的一道闸是在**内网与 Internet 边界部署 ASA5512 防火墙**：逻辑隔离内外网、按预设规则过滤进出数据包、记录所有穿越流量。出口路由器本身内置防火墙能力，和 ASA 形成两层纵深，不是单点设备，而是边界防御链。

## 八、设计权衡：三个容易踩偏的地方

**权衡 1：冗余不是无脑堆设备**

核心双机靠链路聚合、汇聚双上行靠 STP，链路冗余解决的是"断一条不瘫"，而不是"买双倍设备"。成本和可靠性的平衡点就在这。

**权衡 2：信息点按 1000/部门预留够不够**

多留点意味着布线和端口成本上升，但政务终端只增不减。选 1000 点是按五年业务增长倒推的，不是拍脑袋。

**权衡 3：接入层为什么不上高端设备**

接入层是终端接口，性能要求最低、数量最大（360 台）。核心和汇聚的预算占比低但决定全网性能，接入层把钱花在端口密度上比花在性能上划算。

## 九、总结与思考

这份方案从需求清单一路落到设备采购清单：三层拓扑解决了"老网带宽不够、到处冲突"的病根；VLAN + 私网地址把六个部门切成了六个广播域；463 万的设备预算让核心、汇聚、接入三层各得其所；综合布线和边界防火墙把隐蔽工程与安全纵深补齐。

网络规划和写代码不一样：**代码写错了能改线，网线埋进墙里就拔不出来了**。这也是为什么方案里子网掩码选择、信息点预留、设备可升级性，每一个决策都要按"五年后"来倒推。
